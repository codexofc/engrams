# Versioning of the public API

Two mechanisms, and they are not interchangeable.

## URL prefix for breaking versions

`/v1/...` and `/v2/...` are separate route groups, separate controllers under `App\Api\V1` and `App\Api\V2`, and separate OpenAPI documents (`public/openapi/v1.json`, `public/openapi/v2.json`, generated by `bin/console app:openapi:dump`). Shared code lives in `App\Api\Shared`, and the rule is that a V2 controller never imports from `App\Api\V1`.

v1 exists for the 14 carriers with a direct integration (mostly TMS connectors written by their IT providers) and for the driver app builds older than 4.2. It is frozen: no new endpoint, bug fixes only. Its retirement follows [[api-deprecation-policy]].

## Feature header for non-breaking evolutions inside a version

`X-Halden-Features: bids-v2-ranking, load-events-inline`. A comma-separated list of feature names the client understands. The server never changes the shape of a response unless the client asked for it.

Why this instead of `/v3`: most of what we ship is additive but changes semantics slightly (a new bid ranking, an extra state in the load state machine). Bumping the URL version for each of these would have given us `/v7` in a year.

Implementation: `App\Api\Feature\RequestFeatures` is a request-scoped value object populated by `FeatureHeaderSubscriber`. Controllers and serializers ask `$features->has(Feature::BidsV2Ranking)`. The enum `App\Api\Feature\Feature` is the list of accepted names, unknown names are ignored (not an error, so a client can send names before the server ships them).

A feature name is removed from the enum when it becomes the default behaviour, typically after both the web and mobile clients have shipped with it. The removal is a minor release note, not a deprecation.

## What the mobile app sends

Since driver app 4.6 the header is built from a list in `lib/api/features.dart`. When the server drops a feature name, the app keeps sending it, harmless.

## Things that are not versioned

- Webhook payloads have their own `schema_version` field inside the JSON, see [[webhook-delivery-outbox]].
- Error envelope shape, see [[api-error-envelope-convention]].
- Authentication, see [[jwt-auth-and-refresh-tokens]].
